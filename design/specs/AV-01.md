# AV-01. `Aviso` (Unified Notification Type)

## Purpose

Defines the unified notification type for the Avisos system. Replaces `BorderAlertEvent` as the canonical notification model, extending it with product-level event types, read/dismissed state, and deduplication logic. Consumes `CrossingChange` events from LIVE-01's `useLiveCrossingSnapshot`.

## Architecture

```text
CrossingChange (LIVE-01)
     │
     ▼
mapCrossingChangeToAviso()
     │
     ▼
Aviso (unified type)
     │
     ├── AvisosStore (persisted, unread/read/dismissed)
     │        │
     │        ├── Active Trip UI (inline banner)
     │        ├── Avisos Inbox (N01 list using AvisosList)
     │        └── Agent context
     │
     └── Backward compat: mapBorderAlertEventToAviso()
              │
              └── Migration path from existing alerts page
```

## Data types

```typescript
type AvisoType =
  | "crossing_changed"      // STATUS_CHANGE from CrossingChange
  | "wait_surge"            // WAIT_SURGE from CrossingChange
  | "wait_drop"             // WAIT_DROP from CrossingChange
  | "recommendation_changed"
  | "trip_reminder"
  | "checklist_reminder"
  | "data_warning"          // freshness degradation
  | "unusual_condition";

type AvisoSeverity = "info" | "warning" | "critical";

interface Aviso {
  id: string;
  type: AvisoType;
  severity: AvisoSeverity;
  title: string;
  description: string;
  crossingId?: string;
  crossingName?: string;
  previousValue?: string;
  currentValue?: string;
  timestamp: string;
  read: boolean;
  dismissed: boolean;
}
```

## Change → Aviso mapping

| CrossingChange type | AvisoType | Severity |
|---------------------|-----------|----------|
| `STATUS_CHANGE` (open→limited) | `crossing_changed` | `warning` |
| `STATUS_CHANGE` (open/limited→closed) | `crossing_changed` | `critical` |
| `STATUS_CHANGE` (closed→open) | `crossing_changed` | `info` |
| `WAIT_SURGE` (+15min or +40%) | `wait_surge` | `warning` |
| `WAIT_DROP` (-15min) | `wait_drop` | `info` |

## Deduplication

Same crossing + same change type within a time window = no new Aviso.

- `detectCrossingChanges()` only emits on qualifying transitions (not every refresh)
- AvisosStore tracks last emitted change per crossing+type
- Configurable dedup window (default: 30 minutes)

## Lifecycle

```
Aviso created (unread)
     │
     ├── markRead()     → read: true
     ├── markDismissed() → dismissed: true
     └── clearOld()     → removes dismissed avitos older than 7 days
```

## Invariants

1. `Aviso` is the single notification type — no parallel type systems
2. `BorderAlertEvent` is mapped to `Aviso` at consumption, not stored
3. `AlertChangeEvent` (dead code in types/index.ts) is deprecated
4. `AvisosStore` is the single source of truth for notification state
5. `detectCrossingChanges()` produces `CrossingChange[]`; `mapCrossingChangeToAviso()` converts
6. Initial fetch produces no Aviso (no previous baseline)
7. Dedup prevents duplicate Avisos within the configured window
8. `read` and `dismissed` are persisted; `timestamp` is immutable

## Consumer mapping

| Consumer | Reads | Writes |
|----------|-------|--------|
| Active Trip inline banner | unread avitos for current crossing | markRead() |
| Avisos Inbox (N01) | all non-dismissed avitos | markRead(), markDismissed() |
| Agent | full Aviso context | — |
| AvisosBadge | unreadCount() | — |
